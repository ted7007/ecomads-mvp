# Доступ оператора Ecomads

Пользователь `ecomadsops`, сервер `31.76.53.166`, SSH-порт `22`.
Пароль передаётся отдельно и не хранится в репозитории. При первом входе
сервер потребует сменить временный пароль. После смены подключитесь повторно.

```sh
ssh ecomadsops@31.76.53.166
```

После входа рабочий каталог — `/opt/ecomads`; `~/project` ведёт туда же.
Исходники находятся в `/opt/ecomads/releases`. Пользователь может менять их,
читать `.env`, просматривать логи и выполнять команды ниже. Общего sudo и
доступа к Docker-сокету нет. Системные скрипты, Compose и Caddyfile изменяет
владелец VPS. Деплой запускает код на production и даёт ему доступ к данным
приложения, поэтому учётную запись следует передавать доверенному человеку.

```sh
sudo ecomadsctl status
sudo ecomadsctl logs
sudo ecomadsctl restart
sudo ecomadsctl rollback
```

`restart` перезапускает только web. `rollback` переключает приложение на
предыдущий образ; он не откатывает данные БД. `logs` выводит последние 200
строк логов web, caddy и БД; вывод может содержать данные приложения.

## Добавление и изменение секретов

```sh
sudo ecomadsctl secret TELEGRAM_BOT_TOKEN
```

Введите значение в скрытом приглашении. Оно не попадает в аргументы команды
или историю shell. Можно добавлять и менять переменные с префиксами
`TELEGRAM_`, `OPENAI_`, `WB_`, `JWT_`, `POSTGRES_`, `CADDY_`.
Однострочные значения поддерживаются без одинарной кавычки. Пустое значение
очищает секрет. Запись выполняется атомарно после проверки конфигурации;
предыдущее содержимое сохраняется в защищённой резервной копии в `backups`.

Чтобы применить изменения к приложению:

```sh
sudo ecomadsctl apply
sudo ecomadsctl status
```

`apply` архивирует логи и пересоздаёт только web с текущим образом. Это может
ненадолго прервать работу сайта. Обычный `restart` не применяет новые значения
окружения. Сохранение переменной в `.env` само по себе не подключает её к коду:
она должна быть прописана в Compose и поддерживаться приложением. Сейчас
Compose подключает параметры PostgreSQL, JWT и Telegram; новые OpenAI/WB
переменные потребуют соответствующих изменений конфигурации у владельца VPS.
Изменение `POSTGRES_PASSWORD` в `.env` не меняет пароль существующей базы:
ротацию пароля БД нужно согласовать отдельно.

## Деплой исходников

Сначала создайте новый каталог релиза, сохранив структуру
`Ecomads.WebApplication/` и файл `.dockerignore` в корне релиза.
Например, можно скопировать текущие исходники для редактирования:

```sh
cd /opt/ecomads
current=$(cut -d: -f2 .current-image)
version="team-$(date -u +%Y%m%dT%H%M%SZ)"
cp -a "releases/$current" "releases/$version"
```

Измените исходники в `releases/$version`, затем выполните:

```sh
sudo ecomadsctl deploy "$version"
sudo ecomadsctl status
```

Деплой использует существующий production-скрипт с резервной копией БД,
проверкой здоровья и автоматическим откатом при сбое. Хранятся пять последних
релизов: рабочие изменения также храните вне VPS. После деплоя от владельца,
если права чтения `.env` или записи в релизы сбросились, выполните
`sudo ecomadsctl access`. Обычные `ops/deploy.ps1` и `bootstrap-vps.ps1`
предназначены для владельца VPS и напрямую с этой учётной записью не работают.

## Отзыв доступа владельцем VPS

Для блокировки пароля, истечения учётной записи и завершения текущих сессий:

```powershell
ssh my-vps "usermod -L ecomadsops && usermod --expiredate 1 ecomadsops"
ssh my-vps "pkill -KILL -u ecomadsops"
```

Если доступ к секретам больше нельзя доверять, их также нужно сменить.

## Доступ

На новом сервере добавить публичный ключ `~/.ssh/codex_vps.pub` в
`/root/.ssh/authorized_keys`. Сверить ED25519-отпечаток с консолью провайдера.
Локальный SSH-псевдоним `ecomads-new`: root@31.207.76.37, ключ codex_vps,
IdentitiesOnly yes. Старый `my-vps` сохраняется для VPN и восстановления.
Отключать root password login только после проверки нового входа по ключу.

После подготовки /opt/ecomads скопировать рядом три файла:
`provision-vps-operator.py`, `ecomadsctl`, `vps-set-secret.py` и выполнить:

```sh
python3 provision-vps-operator.py ecomadsops1 ecomadsops2
```

Повторный запуск сохраняет пароли. Новые пароли записываются только в
`/root/ecomads-operator-credentials.json` с правами 0600. Каждый коллега обязан
сменить пароль при первом SSH-входе. У каждого отдельная учётная запись;
группа ecomads-access даёт прежние права оператора приложения.
Проверить парольный вход, смену пароля, sudo ecomadsctl status, запись в
releases, отсутствие общего sudo и доступа к Docker-сокету.

## Перенос

1. Снять предварительный экспорт на старом VPS, не останавливая приложение:
   `python3 export-vps-migration.py /opt/ecomads-migration/ИМЯ`.
   Каталог приватный. Проверить SHA256SUMS при каждом копировании.
2. Экспорт включает pg_dump, /opt/ecomads, ключи Data Protection, spool WB,
   данные/конфигурацию Caddy, helper и таймер архивирования логов. PostgreSQL
   volume не копируется. Предварительные counts не являются атомарным снимком;
   окончательное сравнение проводится по финальному экспорту после остановки.
3. Передать точные образы работающих web/db/caddy через docker save/load.
   Дополнительно сохранить предыдущий web-образ, если он доступен.
   Идентификаторы сверять с manifest.json; не пересобирать приложение.
4. Проверить установку Docker/Compose на фактической ОС; открыть SSH/80/443,
   не публиковать PostgreSQL. Восстановить файлы и volumes, не запуская web.
   Поднять только db и выполнить пробный pg_restore --exit-on-error.
5. Сохранить минимум 25% свободного диска после подготовки. На новом диске
   не хранить архив всех старых Docker-образов, временные копии удалить только
   после успешной сверки и сохранения внешней копии.
6. Включить maintenance через старый Caddy, сохранить исходный Caddyfile.
   Остановить старый web корректно, отключить restart policy. Не останавливать
   amnezia-awg2. Исключить параллельные деплои на время переключения.
7. Финальный экспорт: `python3 export-vps-migration.py
   /opt/ecomads-migration/ФИНАЛЬНОЕ_ИМЯ --final`. Повторить передачу и восстановление
   БД, keys, spool, конфигурации и сертификатов. Сверить SHA256SUMS, counts всех
   таблиц и историю миграций до старта web.
8. Запустить точный web-образ и Caddy на новом VPS; проверить HTTPS с
   `curl --resolve ecomads.ru:443:31.207.76.37 https://ecomads.ru/health`.
   Отдельно проверить SQL, страницы, авторизацию и расшифровку WB-токенов.
   /health в текущем образе не проверяет БД.
9. Пользователь меняет DNS: A ecomads.ru = 31.207.76.37; www либо тот же A,
   либо CNAME на ecomads.ru. Удалить/исправить AAAA, ведущий на старый сервер.
   Снизить TTL заранее, проверить авторитетные и публичные DNS после изменения.
10. Старый Caddy временно проксирует на https://31.207.76.37 с TLS server_name
    ecomads.ru и исходным Host, без отключения проверки сертификата. Старый web
    остаётся выключенным. Проверить работу через оба IP и работу VPN.
11. После приёмки сменить значения SshHost по умолчанию в deploy.ps1,
    bootstrap-vps.ps1, rollback.ps1 на ecomads-new, IP в Caddyfile и инструкции.
    Проверить log archive timer и восстановление стека после перезагрузки.

## Известные особенности

При подготовке текущий образ: ecomads:20261020T135351Z-b6a2a69-dirty.
Предыдущий: ecomads:20261020T134103Z-336a559-dirty.
Исходников этих двух релизов в /opt/ecomads/releases нет. Доступные старые
исходники сохраняются в экспорте, но не считаются исходниками текущего образа.
Действующий production Compose и helper сверены отдельно: helper содержит
apply/secret, а старый provisioning-скрипт этих команд не устанавливал.
Новая версия provisioning устанавливает полный актуальный набор команд.
Секреты OpenAI присутствуют в .env, но действующий Compose не подключает их
к web. При переезде сохраняется фактическое поведение, без добавления функций.

## Откат

До запуска нового web: вернуть исходный Caddyfile и restart policy, запустить
старый web. После появления записей на новом сервере: сначала остановить новый
web, снять актуальный дамп и изменяемые файлы, восстановить их на старом сервере,
проверить, затем вернуть DNS/маршрутизацию и запустить старый web.
Простой возврат DNS после новых записей приведёт к потере данных.

Сохранить финальный архив вне нового VPS, старые данные минимум 7 дней.
Старый VPS не удалять: на нём остаётся VPN. После переноса проверить ресурсы,
логи, Telegram polling только на новом сервере и ближайший плановый сбор WB.

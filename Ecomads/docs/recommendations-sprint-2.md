# Рекомендации: второй спринт

Карточки № 3 и № 6 теперь содержат ручное действие, альтернативы, ключевую долю, ограничения и до двух диагностических гипотез. Сервис не изменяет рекламу WB. Расчёт, средняя цена и доля заказанных единиц используют выбранный период; денежная подпись — расход, приведённый к неделе, а не экономия.

## Что видно в кабинете

- На странице кампании: исключение кластера, снижение ставки или проверка карточки; кнопки «Принял», «Отложить», «Не актуально»; итог по уникальным кластерам и маркеры действий в таблице.
- Пять и более доступных исключений № 3 одной кампании объединяются в пакет. Выбор, сумма и копирование работают по выбранным элементам; список разделён по артикулам. Каждый элемент имеет собственный снимок и решение.
- В сводке: пять первых карточек, число остальных, итоги кампаний и фильтр кабинета для рекомендаций. Факты загружаются на сервере пакетно, карточки и таблица кампании используют тот же расчёт и даты.
- В «Нормах»: дата запуска кампании, минимумы показов/кликов/корзин/заказов/расхода для пояснений и нормы конверсий. Пустые нормы конверсии означают сравнение с пригодной группой минимум трёх других кластеров. Норма CTR используется, только если задана в сохранённых настройках; при её отсутствии действует сравнение с группой.
- В кампании, в «Нормах и датах запуска товаров»: дата запуска отдельного товара имеет приоритет, пустая дата наследует дату кампании. Никакая дата запуска не выводится из импортированной статистики.

## Ограничения и действия

Ключевой кластер — не менее 20% Q товара за выбранный период. Неизвестный знаменатель запрещает исключение. При известных Q товара = 0 и Q кластера = 0 доля равна 0; отсутствие заказов не делает кластер ключевым.

№ 3 сохраняет денежный порог max(2 × P × N, 300 ₽), не требует кликов и отдельного подтверждения нерелевантности. № 6 сохраняет Q ≥ 3, сценарий цены и добавление одной единицы. Для ручной CPM-ставки снижение равно min(30%, (1 − N / ДРР) × 100%). Для единой ставки исключение неключевого кластера разрешается при ДРР ≥ 2 × N; ниже — наблюдение. Ключевому кластеру доступно снижение подтверждённой ручной ставки либо проверка товара. Исключённый кластер не получает повторное исключение.

Защита запуска действует для первых 21 календарного дня по МСК и для исторического периода, пересекающего эти дни. Расходные карточки скрыты с указанием причины. Конкретные рекламные действия требуют полной загрузки и конца периода не позднее D−2 по МСК. Это ограничение доступности действия, а не гарантия окончательности WB.

## Источник настроек WB

Тип ставки и платёжная модель сохраняются при существующем импорте `/api/advert/v2/adverts`. Фоновый процесс рекомендаций читает `/adv/v0/normquery/get-bids` и `/adv/v0/normquery/get-minus`, по 100 пар на запрос. Используется проверка токена «Продвижение / Только чтение». Методы с POST здесь только читают данные; setters не реализованы.

Настройки обновляются раз в час при разрешённом автообновлении. Метаданные кампаний повторно используются из штатного импорта, чтобы новый процесс не занимал его лимит. Ставки API хранятся в рублях после преобразования копеек. Успешный пустой список исключений отличается от отсутствующей пары, ошибки доступа и ошибки источника. Настройки старше 24 часов становятся недоступными для рекламных действий. Ошибка обновления сразу делает источник недоступным, даже если сохранён прошлый ответ.

В текущих read-ответах не подтверждены **минимум и шаг конкретной ставки кластера**. Минимум товарной ставки не подставляется вместо них. Поэтому реальные импортированные карточки предлагают процент. Контракт поддерживает текущую ставку, минимум и шаг; точная сумма рассчитывается только при наличии всех трёх, с округлением вверх и проверкой границы 30%. [Документация WB](https://dev.wildberries.ru/en/docs/openapi/promotion).

## API и хранение

Контракт рекомендаций — schemaVersion 2, чтение старых снимков сохранено. Основной сигнал, выбор действия и диагностика разделены на `RecommendationEngine`, `RecommendationActions`, `RecommendationDiagnostics`; представление карточки — отдельный компонент интерфейса.

```text
GET /api/wb/campaigns/{campaignId}/recommendations?startDate=...&endDate=...
GET /api/wb/campaigns/{campaignId}/recommendations/runs/{runId}
GET /api/wb/recommendations/summary?startDate=...&endDate=...&storeId=...
POST /api/wb/campaigns/{campaignId}/recommendations/runs/{runId}/decisions
```

Тело решения: `evaluationIds`, `ruleId`, `status` (`accepted`, `snoozed`, `irrelevant`), `snoozeUntil`, `reason`, `comment`. Откладывание требует будущей даты, отказ — причины. Проверяются владелец кампании/снимка и принадлежность всех выбранных объектов; пакет сохраняется одной транзакцией. Повторные evaluationId учитываются один раз.

Решения добавляются в журнал и привязаны к неизменному снимку. Ответ показывает последнее решение; новые периоды и изменившиеся факты получают отдельные снимки, решения по названиям не переносятся. Снимки с решениями не удаляются 90-дневной очисткой. В снимке сохранены цифры, нормы, действия и время получения использованных настроек WB.

При запуске приложения применяется миграция `AddRecommendationActions`; существующим нормам добавляются стартовые минимумы 1000 показов и 20 корзин. После обновления дождитесь штатного импорта метаданных и фонового чтения настроек, иначе карточка объяснит, почему рекламное действие пока недоступно. Даты запуска следует указать вручную, если требуется защита запуска.

## Проверка

Автоматические проверки охватывают денежные и процентные границы, ключевую долю, запуск и наследование, свежесть периода, неизвестные настройки, отсутствие ограничений ставки, уже исключённый кластер, пригодность группы, собственную цену предыдущего периода, пакеты и выбор части элементов, сохранение решений, очистку и права доступа. HTTP-проверка сверяет runId сводки и кампании. Интерфейс проверен в браузере на обычном и узком экране, включая обязательную дату решения и перерасчёт суммы выбранных элементов.

Автонорма, ростовые действия, остатки, бюджет, LLM, Telegram, обнаружение применения, напоминания и измерение результата остаются вне этого выпуска.

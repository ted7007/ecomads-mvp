# Почему после второго спринта не было рекомендаций

Проверка рабочей базы 14 октября показала:

- В сохранённых расчётах за 7–13 октября у 780 объектов товарный период подтверждён, но кластерный — нет; ещё у 72 не подтверждены оба покрытия. Последняя дата загруженных кластеров была 12 октября.
- Фоновый расчёт проверял отсутствие покрытия для всех наблюдавшихся пар, а постановка загрузки отбирала только пары с доступной fullstats. Недоступные пары заставляли повторно загружать уже покрытые доступные пары за 28 сентября — 4 октября. Следующий интервал не получал очередь.
- За 6–12 октября у 63 объектов оба покрытия были полными, но старые товарные строки не имели `RecommendationFieldsVerified`. Успешный запрос WB и наличие старых строк не означают проверку нужных полей каждого дня.

Исправление:

1. `EnqueueMissingClustersAsync` использует один набор доступных пар для проверки покрытия и постановки загрузки; уже покрытые пары не загружает повторно.
2. Фоновый процесс учитывает недавно выбранные пользователями периоды, затем стандартное окно. Интервал без доступных недостающих пар больше не блокирует следующие интервалы.
3. Импорт `fillMissingOnly` повторно проверяет старые товарные строки при получении действительных данных WB, даже если день ранее помечен загруженным. Отсутствующие строки ответа не превращаются в нули.
4. Карточка и таблица показывают конкретные пробелы: товарный период, кластеры, проверка старых полей.

Выпуск `ecomads:20261014T014218Z-nogit` выложен через изолированную копию базового коммита d776ff5 с шестью исправленными файлами. Перед переключением создан штатный backup базы. Одна ещё не начатая повторная задача старого интервала снята с активного выполнения только после проверки совпадения всех пар с уже завершённой загрузкой; история и статистика сохранены. Код ошибки задачи: `superseded_by_verified_coverage`.

Проверки по рекомендациям, планировщику и разреженным ответам WB: 72/72; frontend production build успешен. Общий прогон: 146/148, две ошибки существующих проверок форматирования Telegram, не относящихся к этому исправлению.

Скачивание недостающих дат продолжает соблюдать текущие лимиты WB. Наличие рекомендаций после загрузки зависит от выполнения денежных правил, нормы и наличия цены за выбранный период; проверки полноты не отключены.

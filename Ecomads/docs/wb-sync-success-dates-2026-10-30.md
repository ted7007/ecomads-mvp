# Дата последней успешной обработки WB

В колонке «Успешная обработка» для рекламы, кластеров и Джема отображалось
30.09 вместо последних обработок 30.10. У нескольких старых завершённых
заданий `completed_at_utc` равен `NULL`, а `updated_at_utc` содержит дату сентября.
PostgreSQL при сортировке `completed_at_utc DESC` помещает `NULL` в начало.
Резервная дата применялась только после выбора записи, поэтому свежие
завершённые задания не попадали в результат.

`WbSyncVisibilityController.Overview` сортирует успешные задания по
`CompletedAtUtc ?? UpdatedAtUtc`, то есть по той же дате, которую возвращает
в `lastSuccessAtUtc`. Сами записи журнала не изменяются.

`WbSyncOverviewTests` проверяет на PostgreSQL выбор последней успешной даты
для трёх затронутых источников, включая случай, когда у самого свежего
успешного задания отсутствует `CompletedAtUtc`. Более поздняя ошибка
не заменяет успешную обработку. Обе проверки прошли на отдельном временном
PostgreSQL 15; рабочая БД для тестов не использовалась.

Серверный релиз `sync-dates-20261030` подготовлен из
`main-20261028T180749Z-8afd89f` с единственной правкой сортировки в контроллере.
Публикация завершена, `/health` возвращает `Healthy`. Проверка рабочего
`sync-overview` подтвердила даты 30.10.2026: реклама 03:16:11 UTC,
кластеры 03:17:32 UTC, Джем 03:17:48 UTC. Перед переключением создана
резервная копия `ecomads-20261030T044625Z-before-sync-dates-20261030.dump`.

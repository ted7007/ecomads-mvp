# Оценочная сумма заказов и ДРР кластеров

Добавлено 07.10.2026. Это отдельные оценочные показатели; фактические KPI кампаний и существующие условия рекомендаций не меняются.

Для выбранных включительно дат `startDate`–`endDate` и одной пары кампания + артикул:

```
Средняя стоимость заказанной единицы = Σ fullstats.sum_price / Σ fullstats.shks
Оценочная сумма заказов кластера = средняя стоимость × Σ cluster.shks
Оценочный ДРР = Σ cluster.spend / оценочная сумма × 100%
```

`orders` не используется в этих формулах. Все суммы берутся только внутри выбранных дат. Без обеих границ периода оценка недоступна. Средняя не округляется до расчёта суммы и ДРР; результаты для отображения округляются до двух знаков. ДРР рассчитывается по неокруглённой сумме.

## Сопоставимость источников

В [официальном журнале WB](https://dev.wildberries.ru/release-notes?id=214) кластерный `shks` описан как количество заказанных товаров. [Контракт fullstats и примеры WB](https://dev.wildberries.cn/docs/openapi/promotion) содержат отдельные `orders`, `shks`, `sum_price` в товарной детализации `days[].apps[].nms[]`. Для средней используется именно количество единиц `shks` и сумма из тех же товарных строк, а не количество заказов `orders` или итог кампании.

Проверены сохранённые локальные ответы `.env.wb-fullstats-response.json` и `.env.wb-normquery-response.json`, без новых запросов статистики и публикации исходных коммерческих данных. В 559 товарных строках fullstats присутствовал `shks`. Для 84 совпавших разрезов кампания + артикул + день сравнили сумму `shks` всех приложений fullstats и сумму `shks` всех кластеров: в 64 случаях значения совпали, в 20 — различались. Это проверка структуры и агрегатов, не доказательство одинаковой атрибуции двух источников. Нельзя требовать равенства итогов или выдавать полученную сумму за фактическую выручку кластера. Предположение оценочной модели: средняя стоимость единицы данной пары за период применима к заказанным единицам её кластера.

Fullstats суммируется исключительно по листовым строкам `nms`, объединяя приложения по товару и дню. Родительские итоги кампании, дня и приложения второй раз не прибавляются. Кластерный `shks` суммируется по дневным строкам одного кластера той же пары.

## Недоступность и полнота

- Миграция `AddArticleOrderedProducts` добавляет nullable `ordered_products` в товарную статистику кампании. Старые строки получают `null`; `orders` не используется для заполнения. После применения миграции требуется повторно загрузить fullstats нужного периода обычным обновлением, а не заполнением только отсутствующих дней.
- Импортер сохраняет сумму `shks` приложений, только если поле присутствует и корректно во всех товарных строках. Отсутствующее значение даже одного приложения делает товарный итог `null`.
- Для средней требуется подтверждение fullstats (`data`/`zero` в проверках кампании) каждого дня периода. При неполном покрытии, отсутствии товарных строк, неизвестном `shks`, отрицательных значениях или нулевой сумме единиц средняя, сумма кластера и ДРР равны `null`.
- Если `shks` любой строки кластера неизвестен, средняя может быть известна, но сумма и ДРР кластера возвращаются `null`.
- При нулевой оценочной сумме возвращается сумма `0` и ДРР `null`.
- Частичная загрузка кластеров допускает предварительную оценку по загруженным строкам. Полнота для этих новых показателей проверяется отдельно по конкретной паре и объединению завершённых задач за все выбранные дни. Старый флаг `isPeriodComplete` для рекомендаций не меняется.
- Период с текущим днём по МСК помечается предварительным, даже если задачи завершились.

API возвращает `orderedProducts`, `averageOrderedUnitPrice`, `estimatedOrderSum`, `estimatedDrr`, `estimateStatus` (`complete`, `preliminary`, `unavailable`) и `estimateReason`. В таблице появились два столбца с пометкой «Оценка», подсказкой формулы и обозначением неполных данных. При недоступности выводится прочерк с причиной в подсказке.

Тесты покрывают взвешенную среднюю, ограничение периода, использование `shks` вместо `orders`, нулевые/неизвестные единицы, нулевую сумму, предварительность, импорт приложений без родительского двойного подсчёта, повторный импорт, изоляцию кампании и артикула, миграцию и API. Реальный WB-токен тестами не используется.

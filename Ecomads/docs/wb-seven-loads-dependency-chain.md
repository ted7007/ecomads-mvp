## Проверка `fullstats` 03.10

В 09:46 МСК отправлен отдельный `GET /adv/v3/fullstats` по трём кампаниям за 02.09–01.10, включая кампанию с ранее сохранённой статистикой. WB ответил `HTTP 429` с JSON `rate limit exceeded` и ID запроса `75f2f02780a6054f9b3bd45394eca0c5`. [Точное тело ответа](../artifacts/build-check-probe/responses/fullstats-diagnostic-429-response.json) и [метаданные запроса](../artifacts/build-check-probe/responses/fullstats-diagnostic-429-metadata.json) сохранены без токена. Предыдущий штатный вызов `fullstats` был в 09:06 МСК; диагностический попал внутрь следующего часа.

В 10:14 МСК, после часового окна, повторили запрос за те же даты: **24 ID из предыдущей пустой пачки + контрольная `35174765`**, у которой ранее были данные. WB вернул `HTTP 200`, массив из **одного объекта** `advertId=35174765` и ни одной из 24 кампаний. [Полный JSON WB](../artifacts/build-check-probe/responses/fullstats-diagnostic-200-response.json) · [запрос, время, заголовки и размер ответа](../artifacts/build-check-probe/responses/fullstats-diagnostic-200-metadata.json). Заголовок `X-RateLimit-Remaining: 0` подтверждает израсходованный слот. Токен в файлы не записан. Диагностический ответ не импортирован в статистику сайта; архивная работа сдвинута за его слот.

Сопоставление показывает, что `null` прежней пачки совместим с отсутствием возвращённых кампаний: при добавлении заведомо рабочей кампании WB вернул её объект, а остальные 24 опустил. Это **не подтверждённые нули расходов** по каждой из 24 кампаний; WB не передал ни явные нули, ни дни, ни причину пропуска. Нельзя доказать по одному такому ответу, что у 22 более старых кампаний никогда не было показов.

Даты кампаний дают отдельную причину части пустоты: `40621607` и `40621599` созданы **02.10 МСК**, уже после конца периода **01.10**. В первой архивной пачке 36 из 50 кампаний имеют подтверждённую дату завершения **до 02.09**. Планировщик всё же включил их в запросы. Это лишние обращения к WB; по этим датам нельзя ожидать статистику за выбранный интервал. Остальные 22 ID текущей повторной пачки по датам однозначно исключить нельзя, поэтому причина их отсутствия пока не доказана.

Таким образом, слово «пусто» у этих методов означает **три разных формы ответа**: всё тело `null` у `fullstats`; объект пары без `dailyStats` у кластеров; отсутствие запрошенного `nmId` в `data.items[]` у Джема. Для воронки проверочные ответы не пустые.

## Какие части JSON реально используются

```text
WB fullstats: [{advertId, days:[{date, sum, sum_price, views, clicks,
                                  atbs, orders, canceled, apps:[{nms:[...]}]}]}]
  → sum / sum_price / views / clicks → рекламные KPI и дневные линии
  → apps[].nms[] → таблица товаров кампании
  → подтверждения кампании и дня → полнота общего ДРР

WB grouped/history: {data:[{currency, history:[{date, orderCount, orderSum,
                                                 openCount, cartCount, buyoutCount, buyoutSum}]}]}
  → сумма по группам за день → «Заказы» и общий ДРР

WB products: {data:{products:[{statistic:{selected:{orderCount,orderSum},
                                           past:{orderCount,orderSum}}}]}}
  → сумма по страницам и двум дням → старая история заказов

WB clusters: {items:[{advertId,nmId,dailyStats:[{date,stat:{normQuery,spend,
                         views,clicks,atbs,orders,shks,avgPos,cpc,cpm,ctr}}]}]}
  → таблица кластеров

WB Jam: {data:{items:[{nmId,text,frequency:{current},weekFrequency,
                        avgPosition:{current},openCard:{current},
                        addToCart:{current},orders:{current}}]}}
  → отдельный отчёт Джема и совпадающие колонки кластеров
```

Это **схемы полей, которые читает код**, не подмена сохранённым сырого ответа. Последний штатный ответ `fullstats` был разобран как JSON `null`, но его сырые байты не сохранены. Отсутствие кампании или товара в массиве не равно явному нулю; `null` всего ответа тем более не равен нулю.

## Внутренние API EcomAds и точка просмотра

Экран загрузок получает статусы из `GET /api/wb/stores/{storeId}/sync-overview`; «Подробности» читает `GET /api/wb/stores/{storeId}/sync-jobs/{jobId}`. Эти методы возвращают **историю задания**, а не тело WB. Сводка читает `GET /api/projects`, `/api/statistics/daily`, `/api/statistics/coverage`; страница кампании дополнительно `/api/statistics/nomenclatures/{id}`, `/api/wb/campaigns/{id}/clusters`, `/api/wb/campaigns/{id}/jam`, `/api/wb/campaigns/{id}/spend-trend`. Состояние свежести обеих страниц приходит из `/api/wb/data-state`.

Чтобы в будущем видеть **последний JSON каждого штатного задания прямо на экране**, потребуется отдельно сохранять ограниченный диагностический снимок при импорте. Новые проверочные запросы выше показывают точные ответы на аналогичные запросы, но не восстанавливают байты прошлых заданий. Снимок потребует ограничения размера и срока хранения и контроля доступа к сведениям о товарах и поисковых фразах.

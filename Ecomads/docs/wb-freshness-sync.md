# Обновление данных Wildberries и подтверждение ДРР

## Порядок загрузки

Кнопка «Загрузить всё из WB» ставит текущую рекламу за последние 30 завершённых дней по МСК и свежие все заказы за 7 дней. Товары из обработанных рекламных пачек сразу передаются в задания кластеров и Джема за 7 дней. Затем проверяются завершённые кампании и дозагружаются недостающие старые дни заказов. Два задания рекламы используют один лимит метода `fullstats`; свежая история заказов и отчёт по товарам используют отдельные лимиты методов воронки. Задание, ожидающее лимита, не мешает готовому запросу другого метода.

Лимиты базового токена: `fullstats` — один запрос (до 50 кампаний, до 31 дня) в час; кластеры — два запроса (до 100 пар кампания–товар, до 7 дней) в час; Джем — один запрос (до 50 товаров, до 7 дней) в час; дневная история и отчёт по товарам воронки — по два запроса в час. Дневная история доступна только за последние 7 дней. Для дней 8–30 используется постраничный отчёт по товарам; при 12 запросах по 30 минут без дополнительной пагинации это около 6 часов. Оценка для этого источника минимальная: большое число страниц увеличит время.

Повторное нажатие использует активные задания соответствующего вида. Архивное задание не мешает новому обновлению свежих данных. Позиция постраничной дозагрузки и накопленные суммы сохраняются в БД между перезапусками. Автозапуск после 06:00 МСК управляется флагом `Wb:AutoRefresh:Enabled` и по умолчанию выключен.

## Полнота и ДРР

Успешный запрос не считается подтверждением всех кампаний. Для рекламного расхода подтверждаются только явно полученные дни кампаний, включая явный ноль. Отсутствующая кампания или день остаётся неизвестным. Заказы подтверждаются для каждого кабинета и дня воронки, включая нулевой день. Ошибка обновления не удаляет ранее сохранённые значения.

Полный ДРР рассчитывается только при подтверждении расхода всех участвующих кампаний и всех заказов всех кабинетов за каждый день периода. Предварительный ДРР использует пересечение подтверждённых дней: сумма расхода за эти дни / сумма всех заказов за те же дни × 100. Если подтверждённых дней нет или сумма заказов равна нулю, показывается «—» с причиной. График оставляет пропуск в неподтверждённый день. Сравнение периодов требует полного покрытия обоих периодов.

На сводке и странице кампании блок свежести показывает статус загрузки, подтверждённый диапазон дат, время проверки, ожидание следующего запроса и оценку завершения. Открытая вкладка проверяет состояние каждые 15 секунд при активной загрузке и раз в минуту без неё; после изменения версии источника обновляются связанные запросы.

## Джем

Отчёты Джема хранятся по собственным периодам. Страница кампании по умолчанию открывает последний доступный отчёт по связанным товарам; переключение общего фильтра 7/14/30 дней не меняет этот выбор. Селектор позволяет выбрать другой сохранённый период. Успешный пустой ответ фиксируется отдельно от отсутствия отчёта. Во время нового запроса предыдущий отчёт остаётся видимым. Значения Джема добавляются в таблицу рекламных кластеров только при точном совпадении дат.

## Проверка после публикации

Проверить `/health`, миграцию `AddWbDataChecksAndMethodSlots` и отсутствие ошибок работника в журнале. Под тестовым входом нажать «Загрузить всё из WB» и убедиться, что сначала выполняются свежие запросы, а архив и старые заказы ожидают собственной очереди. Проверить сводку, кампанию и экран кабинета на настольной и мобильной ширине. На кампании проверить селектор Джема и сохранение отчёта при смене общего периода. При неполной рекламе ДРР должен показывать предварительные подтверждённые дни либо причину отсутствия значения.

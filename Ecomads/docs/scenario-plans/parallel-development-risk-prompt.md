# Prompt for parallel development risk control

Используй этот промпт перед началом крупной frontend-задачи или перед merge/rebase, когда параллельно продолжается разработка legacy-фич.

```text
Проанализируй задачу как migration-risk reviewer.

Контекст:
- Проект EcomAds мигрирует frontend с HTML/CSS/JS на React + TypeScript + Vite + MUI.
- Параллельно на другой ветке продолжается разработка существующих legacy-фич.
- Нельзя останавливать бизнес-разработку.
- Нельзя переписывать весь frontend сразу.
- Новый код желательно держать в Ecomads.WebApplication/ClientApp.
- Legacy frontend находится в Ecomads.WebApplication/wwwroot.

Задача:
<описание задачи>

Проверь и выдай:
1. Какие legacy-файлы эта задача может затронуть.
2. Какие изменения лучше изолировать в ClientApp.
3. Где вероятны merge-conflicts с параллельной веткой.
4. Какие API-контракты нужно зафиксировать до кода.
5. Какие localStorage keys, routes и statuses нельзя менять.
6. Какие части лучше не трогать в этой итерации.
7. Минимальный безопасный план реализации.
8. Минимальный набор ручных проверок после реализации.

Ограничения:
- Не предлагай Redux, Next.js, Tailwind.
- Не предлагай массовое удаление legacy.
- Не меняй backend endpoints без явной причины.
- Отдавай план маленькими этапами.
```

## Короткая версия

```text
Перед реализацией оцени риски параллельной разработки: какие legacy-файлы будут конфликтовать, что изолировать в ClientApp, какие API/localStorage/routes нельзя менять, и предложи минимальный безопасный план без rewrite.
```

## Когда использовать

- Перед переносом очередной страницы.
- Перед изменением auth.
- Перед изменением upload flow.
- Перед изменением sidebar/navigation.
- Перед merge/rebase ветки с параллельной feature-разработкой.
- После появления конфликтов, чтобы выбрать минимальный способ разрешения.

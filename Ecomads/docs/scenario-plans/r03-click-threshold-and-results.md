# R03: достаточность кликов и зависимости результатов

Источник: согласованная поправка Н09 от 20.10.2026 в ТЗ v1.3.

R03 использует CR рекламных заказанных единиц товара к кликам в той же кампании за 30 закрытых дней с концом окна рекомендаций. При неполном покрытии, непроверенных полях или менее 100 кликов используется 2%. Достоверный нулевой CR не заменяется на 2% и не разрешает исключение.

Порог исключения: ноль единиц, расход не ниже max(2 × ДЦЗ; 300 ₽), клики не ниже ceil(3 / CR). Неполные данные кластера блокируют расходные действия. При недостаточных кликах разрешено снижение подтверждённой ручной ставки с учётом минимума; при единой ставке показывается наблюдение с причиной. Неизвестные настройки не дают разрешения на действие.

Основание кликовой проверки сохраняется в presentation.clickEvidence неизменного снимка. Версия R03 — 2; прежние снимки читаются без нового поля и без пересчёта.

## Результат проверки 20 октября 2026

- 100 тестов рекомендаций и API прошли на изолированной PostgreSQL в Docker. Проверены границы кликов и расхода, fallback, нулевой CR, запрет действий при неполных данных, изоляция кампании и товара, полное 30-дневное окно, неизменность и чтение старых снимков.
- `npm run build` прошёл; остаётся предупреждение Vite о размере общего JS-бандла.
- В локальном браузере проверены реальные React-компоненты кампании, сводки и подробностей на синтетических данных при ширине 1440 и 390 px. API-схема принимает как новый результат, так и старый снимок без clickEvidence. Ошибок JavaScript и горизонтального переполнения страницы нет.
- Снимки проверки находятся в `artifacts/build-check-r03/`, протокол тестов — `artifacts/recommendation-tests/r03-results.trx`. Эти файлы — локальные артефакты проверки.
- Изменения не публиковались; коммит и деплой не выполнялись.

## Решения для следующего этапа

- R01: избежанный расход включать в «Сэкономлено» по Н20.
- Смешанные пакеты: вопрос критериев подтверждения и ограничения общей суммы открыт. Денежный результат смешанных пакетов не реализовывать до согласования.
- Порядок: пригодность данных и R03 → сохранение истории настроек и автоопределение → замер → страница «Результаты».
- История настроек, расчёт эффекта, новые рекомендации и страница результатов не входят в исправление Н09.

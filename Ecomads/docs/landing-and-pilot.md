# Лендинг и заявки в пилот

Лендинг `/site` входит в общую сборку React/ASP.NET. Caddy обслуживает тот же
домен; отдельного лендинг-контейнера нет. `/site` доступен всем, `/login` сохраняет
самостоятельное демо на 3 дня. Заявка не создаёт аккаунт и не выдаёт доступ.

## Навигация

- Гость с корня или страницы продукта попадает на `/site?returnTo=…`.
- «Войти» переносит безопасный внутренний адрес на `/login?returnTo=…`.
- После входа восстанавливаются путь, query и якорь; по умолчанию `/dashboard`.
- Сессия проверяется через `/api/auth/me`. Недоступность API предлагает повтор;
  `401`/отсутствующий аккаунт очищает сессию. Выход отправляет на лендинг.
- Контракт JWT и ключи localStorage сохранены. API не перенаправляет гостей в HTML.

## Приём и обработка заявок

`POST /api/pilot-applications` принимает JSON:

```json
{
  "submissionId": "UUID, повторяется при повторной отправке",
  "name": "Имя",
  "contact": "@username или телефон",
  "stores": "one | two-five | over-five | agency | null",
  "budget": "under-100k | 100k-500k | 500k-1m | over-1m | null",
  "jam": "yes | no | unknown | null",
  "contactConsent": true,
  "website": ""
}
```

Ответ `200 {"accepted":true}` возвращается после записи. Повторный `submissionId`
не создаёт дубль, в том числе при конкурентной отправке. Заполненный `website` —
ловушка для ботов: ответ успешный, запись не создаётся. Ошибки: `400`, `413`, `415`,
`429` с `Retry-After`, `503` при недоступности хранения. Публичный ответ не содержит
контакт или идентификатор записи.

Хранилище: таблица `pilot_applications` в существующей PostgreSQL, добавленная
миграцией `20261023160908_AddPilotApplications`. Заявки и контакты удаляются через
180 дней с создания: проверка при запуске и каждые 24 часа. Резервные копии имеют
отдельную действующую ротацию; откат приложения не удаляет таблицу.

Раздел команды: `/admin/pilot-applications`. Показывает по 20 записей, новые сверху,
фильтр статусов, контакт, заметку и редактирование статуса. Статусы:
`new`, `contacted`, `in-pilot`, `closed`, `spam`.

- `GET /api/admin/pilot-applications?page=1&status=new` → `items,total,page,pageSize`.
- `PATCH /api/admin/pilot-applications/{id}` с `status,note` → `204`.
- `GET /api/auth/me` дополнен `canManagePilotApplications`.
- Список пуст по умолчанию: доступ никому не выдаётся. Гость получает `401`,
  пользователь вне списка — `403`. Контакты и содержимое не включаются в логи.

На VPS переменная `PILOT_ADMIN_SELLER_IDS` в защищённом `/opt/ecomads/.env`
содержит разрешённые UUID через запятую. Compose передаёт её в
`PilotApplications:AdminSellerIds`. После изменения нужен перезапуск web.
Администраторы назначаются по UUID существующих аккаунтов, не по email из формы.

## Защита и эксплуатация

- Заявки: 5 попыток на IP за 10 минут, 60 суммарно в минуту,
  максимум 4 одновременно, очередь отключена; JSON не более 8 КБ.
- Вход: 10 попыток в минуту на IP; регистрация: 3 в час на IP.
- CAPTCHA, Telegram-уведомления, CRM и внешняя DDoS-фильтрация не подключены.
- Новая Caddy доверяет цепочке IP только от старого VPS `31.76.53.166` и
  передаёт приложению нормализованный клиентский IP. После завершения переезда
  доверие старому прокси можно удалить отдельным изменением.
- Приложение доверяет только сети Caddy через `TRUSTED_PROXY_NETWORKS`.
  На текущем VPS это `172.19.0.0/16`; при новой установке сверить с
  `docker network inspect ecomads_public`. Не добавлять публичные сети клиентов.
- Статические файлы с хешем в `/assets` кешируются на год; HTML и брендовые
  файлы требуют перепроверки кеша. Caddy включает gzip/zstd.
- По решению владельца политика конфиденциальности пока не опубликована;
  фиктивной ссылки нет. Форма описывает назначение контакта, срок хранения и
  требует отдельного непредустановленного подтверждения связи по заявке.

## Проверки

```powershell
# Требует изолированную PostgreSQL через ECOMADS_TEST_POSTGRES или Docker Testcontainers.
dotnet test Ecomads.WebApplication.Tests --filter "FullyQualifiedName~PilotApplicationsTests|FullyQualifiedName~UserAccessAndFeedbackTests"
cd Ecomads.WebApplication/ClientApp
node --test tests/returnTo.test.mjs
npm run build
```

Проверено 13 backend-тестов и 3 теста адресов возврата. Браузерная проверка:
форма/сохранение/закрытый список/заметка, вход, выход, возврат на кампанию с фильтрами,
ошибка сети и отклонённый JWT без цикла. Макет проверяется на 390, 768 и 1440 px.
Для локального backend по HTTP можно задать `ECOMADS_DEV_API` в ClientApp/.env.local;
по умолчанию dev-proxy сохраняет `https://localhost:5001`.

Деплой: `ops/deploy.ps1`; резервная копия БД создаётся до замены приложения,
миграция применяется при запуске, `/health` проверяется по HTTPS.
Откат: `ops/rollback.ps1`, без удаления миграции и заявок.
